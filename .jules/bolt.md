## 2024-10-27 - Code Splitting WidgetRegistry for Initial Load Performance
**Learning:** The `WidgetRegistry.jsx` contained explicit imports for all widget components, pulling them all into the main application bundle regardless of whether they were immediately needed or displayed on the user's dashboard. In a widget-heavy dashboard architecture like openmun, this is a significant performance anti-pattern.
**Action:** Use `React.lazy()` for all widget imports within `WidgetRegistry.jsx` and implement `<React.Suspense>` at the rendering site (e.g., in `Dashboard.jsx`). This defers the loading of individual widget code until it is explicitly needed by the user, drastically decreasing the initial bundle size and improving the First Contentful Paint (FCP) and Time to Interactive (TTI).
